# Storyboard Schema (storyboard.json)

This document defines the recommended contract for `storyboard.json`, the
creative-direction file the **music** stage reads. It is a companion to
`project_packet_schema.md` and `scenes_schema.md`. A packet references this file
through its `storyboard_path`.

## What this file is

`storyboard.json` carries the campaign/creative context for a single job. On
**every** job — both `silent_brand` and `presenter` — `generate_music.py` loads
it and uses it to author the structured music brief that drives Lyria.

## How the code actually uses it (read this first)

`generate_music.py` requires only that the file **exists** and is **valid
JSON**. It does **not** read any storyboard field by key. It passes the entire
parsed object to Gemini under `"storyboard"`, alongside a separately-computed
`target_duration_seconds` and a `region`, and Gemini authors the brief from it.

Two consequences that matter:

1. **There are no code-enforced required fields.** A storyboard missing every
   field below will still pass the file check and reach the (paid) Gemini brief
   call. Nothing validates its *contents* — not the packet adapter
   (`run_from_packet.py`), not `generate_music.py`. So this schema is a
   **quality contract, not an enforced one**: a sparse or incoherent storyboard
   produces a weak brief and weak music, but it will not be rejected. Treat the
   structure below as required-for-good-results, and review generated music
   before delivery.

2. **The mix duration does NOT come from this file.** The real target length is
   the **voiceover duration** (presenter jobs) or the `--duration` flag / 30s
   default (silent jobs). Any `target_duration_seconds` you put in the
   storyboard is **advisory context for Gemini only** — it does not set the
   final audio length.

## What the music director (Gemini) does with it

The brief stage biases toward polished, modern, gently-rhythmic instrumental
music (the style behind product videos from companies like Stripe, Notion,
Linear, or Apple) **unless** the storyboard explicitly describes stillness,
contemplation, or a somber/serious tone. So the `mood` / `energy` / `intent`
wording you write here is what tips the result between an upbeat bed and a
sparse ambient one.

The `instrumentation` and `avoid` wording flows downstream into the Lyria
prompt. Phrasing that pushes toward generic stock-corporate patterns (the bare
word "beat" was an observed example) raises Lyria's similarity-filter rejection
risk. That risk is now backstopped by an automatic safe-prompt retry, but it is
still better to phrase instrumentation in specific, original terms (e.g. "soft
electronic pulse" rather than "soft beat").

## Recommended shape

```json
{
  "project_name": "string",
  "brand_name": "string",
  "region": "string",
  "target_duration_seconds": 0,
  "format": "string - one line describing the deliverable and whether music is the sole audio or sits under speech",
  "scene": {
    "description": "string - what is on screen",
    "spoken_line": "string - the spoken line, or empty for silent jobs",
    "mood": "string - emotional direction of the scene"
  },
  "music_direction": {
    "intent": "string - what the music should accomplish",
    "instrumentation": "string - the sound palette, in specific original terms",
    "energy": "string - how the energy should behave across the clip",
    "vocal_policy": "instrumental only, no vocals",
    "fade": "string - fade in/out behaviour",
    "avoid": ["string", "..."]
  },
  "notes": "string - any extra context for the music director"
}
```

## Fields

`project_name` — advisory. Names the job for the brief and for human review.

`brand_name` — advisory. The brand the music should feel appropriate for.

`region` — advisory. Note: the actual `region` passed to Gemini comes from
`generate_music.py`'s `--region` flag, not from this field; this field is
context only.

`target_duration_seconds` — **advisory only.** Does not set the mix length (see
above). Useful as context so the brief's internal pacing is sensible, but the
final length is driven by the voiceover duration or `--duration`.

`format` — advisory but high-value. One line stating the deliverable and,
crucially, whether the **music is the entire audio layer** (silent jobs) or
**sits underneath speech** (presenter jobs). This single sentence strongly
steers the brief.

`scene.description` — advisory. What is on screen; helps the music match the
visual tone.

`scene.spoken_line` — advisory. The line spoken on screen, or empty (`""`) for
silent jobs. Informational for the brief; the actual speech is generated by Veo
and (for presenter jobs) converted by STS — it is not produced from this field.

`scene.mood` — advisory, high-value. Tips upbeat-modern vs sparse-ambient.

`music_direction.intent` — advisory, high-value. The clearest place to say
"full-level foreground bed" vs "subtle under-speech bed."

`music_direction.instrumentation` — advisory. Use specific, original terms.

`music_direction.energy` — advisory. "Static/minimal" pushes ambient; "forward
motion / mild build" pushes a more present bed.

`music_direction.vocal_policy` — advisory. Keep instrumental-only; the brief is
forced to `instrumental_only` regardless, but stating it keeps the direction
coherent.

`music_direction.fade` — advisory. Fade behaviour for the bed.

`music_direction.avoid` — advisory, high-value. A list of things the music must
not become. Also your lever for steering away from filter-risky territory.

`notes` — advisory. Anything else the music director should know.

## Silent vs presenter

- **silent_brand:** the music is the *entire* audio layer and plays at full
  level for the whole clip. Signal a present, intentional, engaging foreground
  bed — not a quiet pad hiding under nothing. `spoken_line` is empty. (Reference:
  `silent_bed_proof_storyboard.json`.)
- **presenter:** the music sits *under* the converted speech and fades cleanly.
  Signal a subtle, understated, low-movement under-speech bed. `spoken_line`
  carries the line the presenter says. (Reference: `proof_storyboard_v2.json`.)

## Worked example (presenter, under-speech bed)

```json
{
  "project_name": "Acme onboarding intro",
  "brand_name": "Acme",
  "region": "UK",
  "target_duration_seconds": 8,
  "format": "Short presenter intro clip. Music sits quietly under one spoken line and fades after the speech.",
  "scene": {
    "description": "A professional presenter speaks one short line directly to camera in a bright modern office.",
    "spoken_line": "Welcome to Acme. Let's get you set up.",
    "mood": "calm, professional, premium, understated"
  },
  "music_direction": {
    "intent": "A subtle instrumental bed underneath the spoken line, present but never competing with the voice.",
    "instrumentation": "warm low ambient pad, soft electronic pulse, light texture",
    "energy": "minimal and gentle, no aggressive movement",
    "vocal_policy": "instrumental only, no vocals",
    "fade": "gentle fade in, clean fade out within the clip",
    "avoid": ["vocals", "lyrics", "vocal samples", "commercial jingle", "stock-library cliche", "cinematic swell", "any reference to a specific artist or song"]
  },
  "notes": "Keep the bed quiet so it barely sits under the speech."
}
```

## Relationship to the packet and the external authoring LLM

The packet stays thin and references this file via `storyboard_path`. An
external creative LLM (the human-operated "creative director" layer) produces
this file from raw client inputs. Because the app does not validate the contents
here, the LLM's output should follow this shape closely and a human should
review it before a paid run.
