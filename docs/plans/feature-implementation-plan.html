Feature implementation plan

Eight features, built as a sequence of branches, that extend the video-generation app from single-subject silent jobs to multi-presenter, vertical, post-produced jobs — all driven from the Simple UI.

1Summary of the feature set

This plan adds eight features that together turn the app from a tool for single-subject, silent, 16:9 clips into one that produces multi-presenter, spoken, vertical (9:16) video with branded post-production — entirely from the guided Simple UI. The features fall into three phases. Foundation (F1–F2) fixes the output format to vertical and opens Simple mode up to spoken presenter jobs. Continuity (F3–F5) keeps a subject's face and description consistent across a multi-scene extension chain and curbs unwanted on-screen artefacts. Content, audio & post (F6–F8) ingests the team's existing storyboard template, maps a separate voice to each speaker, and composites a branded end-card after the video is assembled.

2High-level technical implementation plan

Build in dependency order, one branch per feature, each reviewed and merged into the core-features integration branch before the next begins. Keep every change additive and engine-compatible: new packet fields and scene-prompt composition are written by the UI/bridge layer, while the generation engine keeps reading the same scenes/packet contract — so existing silent-brand jobs never regress. Do the foundation first (F1 a single aspect-ratio constant; F2 a presenter job type in Simple mode), because everything else depends on a presenter job existing there. Then the continuity layer (F3, F4, F5) can largely proceed in parallel. Finally the content layer (F6 the template importer; F7 per-speaker voice mapping; F8 the post-production end-card stage). Every feature ships behind the existing free dry-run and spend gates and is QA'd in the Simple UI before merge.

3Final outcome once all features are implemented

An operator can upload the storyboard template the team already fills in and produce a finished vertical (9:16) video end to end from Simple mode: one or more named, visually-consistent presenters carried across a multi-scene extension chain, each with their own human-picked voice, free of gibberish on-screen text, and finished with a branded post-production end-card — all without touching the Admin console or hand-editing any JSON.

Branching method — one feature at a time

feature/<name>→ core-features (integration)→ main (production)
  1. git checkout core-features && git pull — always branch from the latest integration state.
  2. git checkout -b feature/<name> — one branch per feature, following the build waves above (parallel branches are fine once their dependencies are merged).
  3. Implement in small commits; run the test suite and QA the change in the Simple UI.
  4. Open a pull request into core-features; review; merge; delete the branch.
  5. Start the next feature from the freshly-merged core-features.
  6. When all features are merged and QA passes, raise one PR core-features → main.
