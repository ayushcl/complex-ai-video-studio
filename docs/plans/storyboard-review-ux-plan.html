Storyboard review UX — implementation plan

Six UX refinements (F9–F14) to the Simple-mode storyboard-review screen — the rotating image reel, the image size, the review layout, the scenes-to-generate control, and the edit-prompts panel. A separate plan from the F1–F8 generation-pipeline plan; the numbering continues so the two never collide.

1Summary of the feature set

These six changes make the storyboard-review screen calmer and more direct. The rotating reel gets a predictable click-to-lock (replacing the current jittery pause/resume), the focused image becomes a full-width hero, the status badges move to the bottom (only validity + scenes-to-generate stay up top), the scenes-to-generate control becomes an intuitive per-scene slider, and the edit-prompts panel is redesigned as "Adjust Your Scenes" — a full-width editor whose scene selector follows whichever image you've locked onto. All are vanilla-JS/CSS and purely presentational.

2High-level technical implementation plan

Everything lives in ui/static/app.js + styles.css (with a touch of index.html). The work is additive and presentational — the backend (simple_flow.py), the free dry-run, the storyboard render, and the confirm-token spend flow are read-only and unchanged. Build F9–F13 in parallel (they're independent); F14 lands last because it wires the reel's lock state (F9) to the redesigned scene selector (F13). Each ships on its own branch and is verified live in the Simple UI.

3Final outcome once all features are implemented

The storyboard review reads as a focused, predictable screen: a big rotating hero image you click to lock (with a clear lock effect) and click to release; status badges tucked at the bottom with only validity + scene-count on top; an intuitive per-scene slider for how many scenes to generate; and an "Adjust Your Scenes" editor — full-width, centred, with an animated scene selector that follows whichever image you've locked onto.

Branching method — one feature at a time

feature/<name>→ core-features (integration)→ main (production)
  1. git checkout core-features && git pull — branch from the latest integration state.
  2. git checkout -b feature/<name> — F9–F13 can run as parallel branches (independent); F14 after F9 + F13 merge.
  3. Implement in small commits; run python -m unittest discover -s ui/tests -v and QA the change in the Simple UI.
  4. Open a PR into core-features; review; merge; delete the branch.
  5. When all six are merged and QA passes, fold them into the next core-features → main release.
